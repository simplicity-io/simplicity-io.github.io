Phone rankings

How fast phones run AI on the phone itself, measured with OnDevice AI Meter. Every phone ran the same tests with the same models and inputs, and only correct answers count. The score adds up six tests; a phone as fast as our reference phone scores 1,000 per test, 6,000 in total. A higher score means faster on-device AI. How the tests work: Methodology.

The list starts small and grows as we test more phones, in our lab and on Firebase Test Lab. Phones are listed by the best full run we have; runs that stopped early (for example for heat) are not ranked.

Large gaps between phones come mostly from the AI processor (NPU): some chip makers open it to apps and others do not, so on some phones the tests can use it and on others they run on the CPU and graphics processor. See why AI processors differ between phones.

Note on phones limited to Android's older AI route (NNAPI). On some phones, Google Pixel (Tensor) among them, apps can reach the AI processor only through NNAPI, an older Android interface that Google has deprecated; the newer route is open only to approved apps or needs the chip maker's own tools. Our results for these phones show what an ordinary app can get today, which may be well below what the hardware can do with the maker's own software. A lower score here is not a judgement of the chip itself.

Making older runs comparable

The tests were refined over time. Older runs are converted to today's scale rather than left out:

  • ¹ Measured with an earlier version of the tests. The scoring targets (the reference phone's times) changed once. Each test score is the reference time divided by the phone's time, so it converts exactly to today's targets. Checked on two phones tested both ways (ROG Phone 7, motorola edge 50 fusion): the converted test scores came within 3% of the new runs (speech within 10%).
  • ² Measured with 4 processor threads. Since app 1.0.4 the tests use one thread per fast core (4 to 8). Phones with more than 4 fast cores may score a little higher in tests where the main processor (CPU) was their fastest; other tests are unchanged.
  • ³ Image style estimated. The image style test was added later. For phones tested before that, it is estimated from the phone's other five tests, using the typical ratio of the phones that ran it (1.22).
  • ⁴ AI multitasking (since app 1.1.6, not part of the score): how many camera-like AI jobs (object detection at 30 frames per second each; a lighter photo job where the AI processor can't run detection) the phone's fastest correct AI or graphics processor keeps on time while an ordinary job uses the other fast CPU cores and keeps at least 80% of its speed. Steps of 1, 2, 4, 8, 16 jobs and up; levels Limited (0-1), OK (2-4), Good (8), Excellent (16 or more). The phone's latest measurement is shown. "-" = not measured yet with today's method. This replaces the earlier "CPU work saved" column: nearly every phone with a usable AI or graphics processor saved 92-100% of the CPU work, so it hardly told phones apart.
  • ⁵ Chat measured with the earlier chat model. Since app 1.0.14 (suite 5) the chat test runs Gemma 3 1B on every phone. Phones tested before that ran Qwen3 1.7B, scored against the reference phone running the same Qwen model, so their chat score shows how they compared then, not a Gemma measurement. A new run replaces it.
